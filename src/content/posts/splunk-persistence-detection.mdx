    | search key=<key_name>

These notes combine two MITRE ATT&CK persistence techniques and their Splunk
searches. They also explain how to prepare Linux auditd logs for Splunk.

## Screensaver hijack (T1546.002)

Windows runs the configured `.scr` file when the screensaver starts. Changing
the `SCRNSAVE.EXE` registry value can provide
[event-triggered execution](https://attack.mitre.org/techniques/T1546/002/).
The useful records are a registry change (Sysmon EventCode 13), the `reg add`
process that makes the change (EventCode 1), and the file being written to disk
(EventCode 11).

```splunk-spl
index=sysmon (EventCode=13 Details="c:\\windows\\system32\\*.scr" TargetObject="*\\Control Panel\\Desktop\\SCRNSAVE.EXE" ) OR (EventCode=1 CommandLine="reg*\ add *\\Control Panel\\Desktop\" /v SCRNSAVE.EXE /t REG_SZ /d *C:\\WINDOWS\\System32\\*.scr*")
| rex field=CommandLine "/d\ \"(?<TargetFilename>\S+)\""
| eval TargetFilename=coalesce(TargetFilename, Details)
| eval TargetFilename=lower(TargetFilename)
| mvexpand User
| search NOT User="NOT_TRANSLATED"
| join TargetFilename [ search index=sysmon EventCode=11 TargetFilename="C:\\Windows\\System32*.scr" | eval TargetFilename=lower(TargetFilename) | fields TargetFilename Image ]
| table UtcTime EventCode Sid ProcessGuid ProcessId User ComputerName TargetFilename Image
```

## Accessibility feature abuse (T1546.008)

The "sticky keys" technique replaces a Windows accessibility program, such as
`sethc.exe`, `utilman.exe`, or `osk.exe`, with `cmd.exe`. This can open a
SYSTEM command prompt from the login screen.
[T1546.008](https://attack.mitre.org/techniques/T1546/008/) can appear as writes
to those filenames.

```splunk-spl
index=sysmon (EventCode=13 TargetObject IN (*osk.exe*, *sethc.exe*, *utilman.exe*, *magnify.exe*, *narrator.exe*, *DisplaySwitch.exe*, *atbroker.exe*)) OR (TargetFilename IN (*osk.exe*, *sethc.exe*) EventCode=11)
| eval TargetFile=coalesce(TargetObject, TargetFilename)
| mvexpand User
| search NOT User="NOT_TRANSLATED"
| table TargetFile UtcTime Sid ProcessGuid ProcessId User ComputerName
```

The original notes link each technique to its corresponding Atomic Red Team
test: [T1546.002](https://github.com/redcanaryco/atomic-red-team/blob/5c1e6f1b4fafd01c8d1ece85f510160fc1275fbf/atomics/T1546.002/T1546.002.md)
and [T1546.008](https://github.com/redcanaryco/atomic-red-team/blob/5c1e6f1b4fafd01c8d1ece85f510160fc1275fbf/atomics/T1546.008/T1546.008.md).

## Getting auditd logs into Splunk

auditd records events on Linux systems so administrators and analysts can
investigate security incidents. Rules control what it records. [This example
ruleset](https://github.com/Neo23x0/auditd/blob/master/audit.rules) shows how
rules are written, and Red Hat provides a [guide to configuring
auditd](https://www.redhat.com/sysadmin/configure-linux-auditing-auditd).

By default the logs land in `/var/log/audit` (changeable in
[`auditd.conf`](https://man7.org/linux/man-pages/man5/auditd.conf.5.html)) as
ASCII key-value pairs. Some values, such as `proctitle`, are hex-encoded.
`ausearch -i` decodes them at the command line, but importing into Splunk you
have to decode them yourself.
